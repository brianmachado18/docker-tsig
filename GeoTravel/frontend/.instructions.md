# GeoTravel Frontend - Instrucciones de Desarrollo

## 🎯 Objetivo
Construir un frontend moderno en **React (Vite) + OpenLayers + PostGIS** para gestión de recorridos turísticos con información geográfica.

## 📋 Contexto del Proyecto

### Stack Tecnológico
- **Frontend**: React 18+ con Vite
- **Mapas**: OpenLayers + GeoServer (WMS/WFS)
- **Datos Geoespaciales**: PostGIS (mediante servicios GeoServer)
- **Styling**: Tailwind CSS + Design System (Material 3)
- **HTTP Client**: Axios o Fetch API
- **Estado**: Zustand o Context API
- **TypeScript**: Recomendado
- **Build**: Vite

### Design System
- **Paleta de Colores**: Definida en Tailwind (Material 3 Light)
- **Tipografía**: Inter (weights: 400, 600, 700, 900)
- **Iconos**: Material Symbols Outlined
- **Espaciado**: Sistema consistente (gutter: 1rem, container-padding: 1.5rem)
- **Bordes**: Rounded corners minimalistas (DEFAULT: 0.125rem, lg: 0.25rem, xl: 0.5rem, full: 0.75rem)

### Colores Temáticos (por funcionalidad)
- **Estados de Recorridos**:
  - `status-available` (#2f855a) - Disponible
  - `status-pending` (#ed8936) - Pendiente
  - `status-off-season` (#718096) - Fuera de estación
  - `status-cancelled` (#e53e3e) - Cancelado
- **Entidades Geográficas**:
  - `primary` (#002045) - Zonas
  - `secondary` (#0a6c44) - Recorridos
  - `attraction-marker` (#805ad5) - Atracciones

## 🗺️ Integración con OpenLayers + GeoServer

### Configuración Base de OpenLayers
```javascript
// Ejemplo de inicialización de mapa
import Map from 'ol/Map';
import View from 'ol/View';
import TileLayer from 'ol/layer/Tile';
import OSM from 'ol/source/OSM';
import { fromLonLat } from 'ol/proj';

const map = new Map({
  target: 'map',
  layers: [
    new TileLayer({
      source: new OSM() // Base map
    })
  ],
  view: new View({
    center: fromLonLat([-56, -33]), // Centro inicial (Uruguay)
    zoom: 10
  })
});
```

### Servicios GeoServer
- **WMS** (Web Map Service): Capas de fondo, zonas, recorridos
- **WFS** (Web Feature Service): Lectura/escritura de entidades (zonas, recorridos, atracciones)
- **GeoJSON**: Formato de intercambio recomendado

### Capas del Mapa
1. **Capa Base**: OpenStreetMap o similar
2. **Zonas Turísticas**: Polígonos con filtros por atractivo (1-5)
3. **Recorridos**: Líneas/polígonos con color según estado
4. **Atracciones**: Puntos con marcadores específicos
5. **Búsqueda**: Resultados de consultas geográficas

## 📊 Funcionalidades Clave

### Administrador
- **ABM Zonas**: Crear, editar, eliminar con editor geométrico (polígonos)
- **ABM Recorridos**: Gestión con estados y estacionalidad
- **ABM Atracciones**: Catalogación de puntos de interés
- **Cambio de Estado**: Transiciones lógicas entre estados
- **Histórico**: Registro de cambios con timestamps
- **Reportes**: Filtrados por zona, estado, estacionalidad

### Consultas Geográficas
- Recorridos dentro de zona seleccionada
- Zonas con más recorridos activos
- Recorrido más cercano a intersección de calles
- Zona por dirección
- Puntos más populares (en más recorridos)

### Usuario Invitado (Portal Invitado)
- Visualización de mapa público con filtros interactivos
- Vista de recorridos disponibles y su estacionalidad
- Información y catálogo de puntos de interés
- Restricciones: Sin permisos de edición, diseño enfocado en experiencia (ver `Portal_Invitado.html`)

## 🔄 Flujos de Datos

### Flujo ABM Zonas
1. Usuario crea polígono en mapa
2. Valida no superposición con otras zonas
3. Completa formulario (nombre, descripción, nivel atractivo, observaciones)
4. Envía WFS-T al backend (GeoServer)
5. Actualiza capa en mapa
6. Almacena en PostGIS

### Flujo Recorridos
1. Usuario selecciona zona y atracciones
2. Define orden de visitación
3. Establece periodo estacional (ej: marzo-diciembre)
4. Selecciona tipo de experiencia
5. Sistema calcula estado automático según fecha
6. Registra en base de datos con referencias geométricas

## 🚀 Consideraciones de Performance

- Lazy load de componentes (React.lazy + Suspense)
- Virtualización de listas largas
- Debouncing en búsquedas y filtros
- Caching de datos GeoServer
- Minimización de re-renders (useMemo, useCallback)
- Code splitting por rutas

## 🔐 Autenticación & Autorización

- Separar vistas Admin vs Guest
- Validar permisos en client-side (UX)
- Validar permisos en server-side (seguridad)
- Guardar token JWT en localStorage o cookies seguras

## 📝 Convenciones de Código

- Nombres de archivo: PascalCase para componentes, camelCase para archivos de lógica
- Props destructuradas en componentes
- Custom hooks con prefijo `use`
- Exports nombrados en servicios
- Comentarios para lógica compleja y explicación de GIS
- ESLint + Prettier configurados

## 🔗 Integración con Backend

- Endpoint base: `http://localhost:8080/api`
- GeoServer: `http://localhost:8080/geoserver`
- CORS habilitado en backend (usar credenciales si es necesario)
- Documentación de API disponible en Swagger/Springdoc
